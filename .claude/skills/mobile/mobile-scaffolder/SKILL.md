# Mobile Scaffolder

Constitution (when the project has one): `docs/mobile/ARCHITECTURE.md` §0–§2, §11.
**Principle:** boilerplate is generated by the CLI/config, not the LLM. Run these
steps, then fill in feature-specific code. Install **only what the app uses
now** — push, biometrics, Sentry, Universal Links, a component kit are added on
demand by the other `mobile-*` skills.

## 0. Where the app goes (fixed repo folder structure)

Inputs: `NAME` — the project name in kebab-case (same one as
`backend/<name>-api`); `BUNDLE` — reverse-DNS identifier (e.g. `com.acme.billing`).

```text
<repo>/
├── backend/<name>-api/
├── frontend/<name>-ui/
├── mobile/
│   ├── <name>-app/          # the mobile app — this skill's default target
│   └── <name>-<app>-app/    # a separate mobile app — only when the user asks for one
└── docs/
```

- Every mobile app is its **own folder under `mobile/`**: the main one is
  `<name>-app`, any other is `<name>-<app>-app` where `<app>` is the name the
  user asked for, kebab-cased. Never scaffold at the repo root.
- `mobile/` is created only when a mobile app is requested.
- Below, all paths are relative to `mobile/<name>-app/`.

## 1. Create the app
```bash
mkdir -p mobile && cd mobile
npx create-expo-app@latest "$NAME-app" --template default
cd "$NAME-app"
npm run reset-project          # removes the template's example screens
rm -rf app-example             # on-demand rule: no sample code left behind
mkdir -p src && mv app src/app # Expo Router reads src/app
```
Native dependencies always go in with **`npx expo install`** (SDK-matched
versions), plain JS ones with `npm i`:

```bash
npx expo install expo-dev-client expo-secure-store react-native-mmkv \
  @react-native-community/netinfo react-native-safe-area-context \
  react-native-reanimated react-native-gesture-handler expo-image expo-constants
npm i @tanstack/react-query @tanstack/react-query-persist-client \
  @tanstack/query-sync-storage-persister zustand zod react-hook-form @hookform/resolvers
npm i -D eslint-plugin-boundaries prettier orval
```

## 2. Native workflow: CNG + dev build (never commit native folders)
```gitignore
# .gitignore — native projects are generated artifacts
/ios
/android
```
```bash
npx expo run:ios        # or run:android — prebuilds + installs the dev build locally
# no Mac / no local toolchain: eas build --profile development --platform all
npx expo start          # day-to-day: Metro against the installed dev build
```
Any native setting goes in `app.config.ts` via a config plugin. If a step in any
doc says "open Xcode / edit AndroidManifest.xml", find the plugin instead.

## 3. `app.config.ts` — one config, three variants
Replace `app.json` with a typed dynamic config:

```ts
import type { ExpoConfig } from "expo/config";

const variant = (process.env.APP_VARIANT ?? "development") as "development" | "preview" | "production";
const suffix = { development: ".dev", preview: ".preview", production: "" }[variant];
const label  = { development: " (Dev)", preview: " (Preview)", production: "" }[variant];

const config: ExpoConfig = {
  name: `Acme${label}`,
  slug: "acme-app",
  scheme: `acme${suffix.replace(".", "-")}`,        // deep links + OAuth redirect
  version: "1.0.0",
  orientation: "portrait",
  userInterfaceStyle: "automatic",                  // dark mode follows the system
  newArchEnabled: true,
  ios:     { bundleIdentifier: `com.acme.app${suffix}`, supportsTablet: true },
  android: { package: `com.acme.app${suffix}`, edgeToEdgeEnabled: true },
  plugins: ["expo-router", "expo-secure-store"],    // grows one plugin per adopted capability
  experiments: { typedRoutes: true },
  runtimeVersion: { policy: "fingerprint" },        // see mobile-release
};
export default config;
```
Distinct identifiers per variant let all three install side by side. `eas.json`
(profiles that set `APP_VARIANT`) belongs to the `mobile-release` skill — create
only the `development` profile now if you need a cloud dev build.

## 4. TypeScript strict (`tsconfig.json`)
```jsonc
{ "extends": "expo/tsconfig.base",
  "compilerOptions": {
    "strict": true, "noUncheckedIndexedAccess": true, "noImplicitOverride": true,
    "paths": { "@/*": ["./src/*"] } },
  "include": ["**/*.ts", "**/*.tsx", ".expo/types/**/*.ts", "expo-env.d.ts", "nativewind-env.d.ts"] }
```

## 5. Folder structure (create up front)
```bash
mkdir -p src/components src/features src/shared/api src/shared/config src/shared/storage src/shared/hooks
```
```text
src/app/          route files + layouts ONLY (mobile-navigation skill)
src/features/     one folder per domain: api/ components/ hooks/ screens/ stores/ types/ index.ts
src/components/   UI primitives: Screen, Text, Button, Input (mobile-ui-patterns skill)
src/shared/       httpClient, generated API, storage, config, platform hooks
```
Feature anatomy and the `index.ts` boundary are the `feature-architecture`
skill's — identical to web, plus a `screens/` folder.

## 6. NativeWind
Follow NativeWind's install guide **for the installed Expo SDK** (the Babel/Metro
wiring changes between majors); the resulting shape is:

- `tailwind.config.js` — `presets: [require("nativewind/preset")]`,
  `content: ["./src/**/*.{ts,tsx}"]`, and the project's design tokens in
  `theme.extend` (same token names as the web app when there is one).
- `global.css` with the Tailwind directives, imported once in `src/app/_layout.tsx`.
- `metro.config.js` wrapped with `withNativeWind(config, { input: "./global.css" })`.
- `babel.config.js` using the NativeWind JSX transform; `nativewind-env.d.ts`.

Check NativeWind's supported-SDK note **before** every Expo SDK upgrade.

## 7. ESLint encodes the architecture
```bash
npx expo lint          # installs eslint + eslint-config-expo (flat config)
```
Add the boundary rules to `eslint.config.js`:
```js
settings: { "boundaries/elements": [
  { type: "app",       pattern: "src/app/**" },
  { type: "feature",   pattern: "src/features/*", capture: ["name"] },
  { type: "component", pattern: "src/components/*" },
  { type: "shared",    pattern: "src/shared/*" } ] },
rules: {
  "boundaries/element-types": ["error", { default: "disallow", rules: [
    { from: "app",       allow: ["feature", "component", "shared"] },   // routes are the top
    { from: "feature",   allow: ["shared", "component", ["feature", { name: "${from.name}" }]] },
    { from: "component", allow: ["shared"] },
    { from: "shared",    allow: ["shared"] } ] }],                      // nothing imports app/
  "import/no-cycle": "error",
  "@typescript-eslint/no-explicit-any": "error",
  "no-restricted-imports": ["error", { paths: [
    { name: "@react-native-async-storage/async-storage", message: "Use MMKV (shared/storage) or expo-secure-store." } ] }],
}
```

## 8. Typed env (`src/shared/config/env.ts`)
```ts
const schema = z.object({ EXPO_PUBLIC_API_URL: z.string().url() });
export const env = schema.parse({ EXPO_PUBLIC_API_URL: process.env.EXPO_PUBLIC_API_URL });
```
`EXPO_PUBLIC_*` is inlined into the bundle — **public by definition**. Never put
a secret there. `.env.local` (git-ignored) for local values:

| Running on        | `EXPO_PUBLIC_API_URL`              |
|-------------------|------------------------------------|
| iOS simulator     | `http://localhost:8080`            |
| Android emulator  | `http://10.0.2.2:8080`             |
| Physical device   | `http://<machine-LAN-IP>:8080`     |

The API comes from the repo's compose stack (`docker compose up -d` at the repo
root — `local-dev-environment` skill). The mobile app is **not** a compose
service and needs no CORS entry.

## 9. API client generated from OpenAPI
```ts
// orval.config.ts — types + Zod schemas from the backend's document
export default { api: {
  input: "http://localhost:8080/openapi/v1.json",
  output: { target: "src/shared/api/generated/api.ts", client: "fetch", mode: "tags-split",
            override: { mutator: { path: "src/shared/api/httpClient.ts", name: "http" } } } } };
```
```jsonc
"scripts": { "api:generate": "orval" }
```
Generated files are committed and **never hand-edited**; features wrap them in
query hooks (`mobile-data-offline`). The `http` mutator (auth header, refresh,
version headers) is written by the `mobile-auth` skill.

## 10. Provider shell (`src/app/_layout.tsx`)
```tsx
import "../../global.css";

export default function RootLayout() {
  return (
    <GestureHandlerRootView style={{ flex: 1 }}>
      <SafeAreaProvider>
        <QueryProvider>          {/* mobile-data-offline: persisted + connectivity-aware */}
          <Stack screenOptions={{ headerShown: false }} />
        </QueryProvider>
      </SafeAreaProvider>
    </GestureHandlerRootView>
  );
}
export { ErrorBoundary } from "@/components/ErrorBoundary";   // root recovery screen
```
Keep it structural. Route groups and the auth guard: `mobile-navigation`.

## 11. Tests, scripts, verify
```bash
npx expo install jest-expo jest @types/jest --dev
npm i -D @testing-library/react-native msw
```
```jsonc
"jest": { "preset": "jest-expo", "setupFilesAfterEnv": ["<rootDir>/src/shared/test/setup.ts"] },
"scripts": {
  "start": "expo start", "ios": "expo run:ios", "android": "expo run:android",
  "lint": "expo lint", "typecheck": "tsc --noEmit", "test": "jest", "doctor": "expo-doctor",
  "api:generate": "orval" }
```
```bash
npm run typecheck && npm run lint && npm test -- --passWithNoTests && npx expo-doctor
```
Then run it for real: the dev build launches on an **iOS simulator and an
Android emulator** and reaches the API. Green skeleton before any feature work.
